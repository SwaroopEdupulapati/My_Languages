0. Introduction to Java & Java Features (Topics 1 & 2)

A. Introduction to Java (Topic 1)

  • Origin: Developed by James Gosling and his team at Sun Microsystems in 1995 (initially named Oak).
  • Design Philosophy: Simple, Object-Oriented, Platform-Independent, and Secure programming language.
  • Java Platform Editions:
    1. Java SE (Standard Edition): Core Java API, JVM, fundamental libraries for desktop and console applications.
    2. Java EE / Jakarta EE (Enterprise Edition): Enterprise distributed applications, Servlets, JSP, Web Services, EJB.
    3. Java ME (Micro Edition): Lightweight profile for embedded systems, sensors, and mobile micro-devices.

B. Primary Features of Java (Topic 2)

  1. Platform Independent (WORA - Write Once, Run Anywhere): Source code (.java) compiles into bytecode (.class) that executes on any OS equipped with a Java Virtual Machine (JVM).
  2. Simple & Familiar: Eliminates complex, error-prone C++ concepts like explicit pointers, operator overloading, and multiple class inheritance.
  3. Object-Oriented: Everything in Java is associated with classes, objects, and principles (Encapsulation, Inheritance, Polymorphism, Abstraction).
  4. Robust: Strong memory management, automatic Garbage Collection, lack of raw pointers, and strict runtime Exception Handling.
  5. Secure: Runs inside the JVM sandbox; bytecode verification prevents malicious memory attacks and buffer overflows.
  6. Architecture-Neutral: Primitive data type sizes and behavior are fixed across all CPU architectures (e.g., int is strictly 4 bytes on both 32-bit and 64-bit platforms).
  7. Portable: Bytecode specification and standard libraries guarantee identical behavior regardless of operating system or hardware.
  8. Multithreaded: Built-in native support for concurrent thread execution and synchronization primitives to maximize CPU utilization.
  9. High Performance: Employs an intelligent Just-In-Time (JIT) Compiler inside HotSpot JVM to compile frequently executed bytecode directly into native machine code.
  10. Distributed & Dynamic: Native networking (java.net), Remote Method Invocation (RMI), dynamic class loading on demand.

1. Structure of a Java Class & Source File (Topic 5)

A standardized Java source file (.java) follows a well-defined structural hierarchy:

1. Documentation Section   --> /** API Documentation comments */
2. Package Statement        --> package com.cdac.training; (Optional, 1st line of code)
3. Import Statements       --> import java.util.Scanner; (Optional, 0 or more)
4. Interface Statements    --> interface Service { ... } (Optional)
5. Class Declaration       --> public class Employee { ... } (Mandatory)
   ├── Static Variables    --> Shared class-level state
   ├── Instance Variables  --> Per-object instance state
   ├── Constructors        --> Object initialization logic
   ├── Methods             --> Object behavior and business logic
   └── Main Method         --> Entry point: public static void main(String[] args)

Rule: In any .java file, there can be at most one public class, and the file name must exactly match that public class name.

User Input in Java (Scanner Class)

Overview

In Java, standard user input from the console (keyboard) is most commonly handled using the Scanner class, located in the java.util package. It reads raw input bytes from System.in and parses them into primitive data types (int, double, boolean) and String objects.

How It Works

  1. Import the Class: Include import java.util.Scanner; at the top of your file.
  2. Instantiate the Object: Create a Scanner instance linked to the standard input stream:
    Scanner scanner = new Scanner(System.in);
  3. Read Input: Call the appropriate method based on the expected data type. The program pauses execution until the user types data and presses Enter.
  4. Close the Resource: Call scanner.close() when finished to release the underlying input stream and prevent resource leaks.

Code Example

import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.print("Enter your name: ");
        String name = scanner.nextLine();

        System.out.print("Enter your age: ");
        int age = scanner.nextInt();

        System.out.println("Hello " + name + ", you are " + age + " years old.");

        scanner.close();
    }
}

Common Scanner Methods

Data Type Method Behavior
String (Full Line) nextLine() Reads all characters until a newline (\n) is encountered.
String (Single Token) next() Reads characters up to the first whitespace (space, tab, or newline).
int nextInt() Parses the next token as a 32-bit signed integer.
double nextDouble() Parses the next token as a double-precision floating-point number.
boolean nextBoolean() Parses the next token as true or false (case-insensitive).
char next().charAt(0) Reads the next token and extracts the character at index 0.

Key Concepts & Pitfalls

1. The nextLine() Buffer Issue

Numeric methods like nextInt() and nextDouble() read only the number and leave the trailing newline character (\n) in the input buffer. If nextLine() is called immediately afterward, it consumes that leftover newline and returns an empty string.

  • Solution: Add an extra scanner.nextLine(); after reading numeric input to clear the buffer before reading a string line.

2. Input Validation (InputMismatchException)

If a user enters data that does not match the expected type (e.g., typing "abc" when nextInt() is called), Java throws an unchecked InputMismatchException at runtime.

  • Solution: Validate input beforehand using methods like scanner.hasNextInt() or handle errors gracefully using a try-catch block.

3. Alternative Input Classes

  • BufferedReader (java.io): Reads text as raw character streams without automatic parsing. It has a larger buffer size and is significantly faster than Scanner for reading large volumes of data (commonly used in competitive programming).
  • Console (java.io): Useful for reading sensitive input like passwords without echoing characters to the terminal via readPassword().

4. Type Casting

Type casting is converting a value from one data type to another. Java has two types of casting:

  1. Implicit Casting (Widening / Automatic):

    • Happens automatically when converting a smaller type to a larger type.
    • No data loss.
    • Order: byte → short → char → int → long → float → double

  2. Explicit Casting (Narrowing / Manual):

    • Must be done manually using parentheses (targetType) value.
    • Converting larger type to smaller type; potential data truncation/overflow.
    • Order: double → float → long → int → char → short → byte

B. Data Type Compatibility & Numeric Type Promotion (Topic 9)

In Java, types are compatible if values of one type can be assigned or converted to another:

  1. Widening Hierarchy (Fully Compatible / Safe): byte →\rightarrow→ short →\rightarrow→ int →\rightarrow→ long →\rightarrow→ float →\rightarrow→ double char →\rightarrow→ int No explicit cast required; handled automatically by the compiler without data loss.

  2. Narrowing Hierarchy (Incompatible without Explicit Cast): double →\rightarrow→ float →\rightarrow→ long →\rightarrow→ int →\rightarrow→ short →\rightarrow→ byte Requires explicit (TargetType) cast; may result in truncation, overflow, or precision loss.

  3. Automatic Numeric Promotion in Expressions:

    • Operands of type byte, short, and char are automatically promoted to int before arithmetic evaluation.
    • If one operand is double, the entire expression evaluates to double.
    • Otherwise, if one operand is float, the result is float.
    • Otherwise, if one operand is long, the result is long.

6.6 Bitwise and Bit-Shift Operators

Bitwise operators operate directly on individual bits (binary 0s and 1s) of integer types (byte, short, int, long, char).

& Bitwise AND a & b 1 only if both corresponding bits are 1 5 & 3 → 0001 (1)

1. How Bitwise Operators Work

Let's take two integer values: a = 5 (Binary: 0101) and b = 3 (Binary: 0011).

A. AND (&) Returns 1 only when both corresponding bits are 1.

   0101  (5)
 & 0011  (3)
 --------
   0001  (1)

B. OR (|) Returns 1 if at least one of the corresponding bits is 1.

   0101  (5)
 | 0011  (3)
 --------
   0111  (7)

C. XOR (^) Returns 1 only when the corresponding bits are different (one is 1, the other is 0).

   0101  (5)
 ^ 0011  (3)
 --------
   0110  (6)

D. Complement (~) Inverts all bits. Note that Java uses 32-bit signed integers (two's complement representation). When you invert a positive number, the sign bit flips to 1, making it negative. 

 ~ 0000 0000 0000 0000 0000 0000 0000 0101  (5)
 -----------------------------------------
   1111 1111 1111 1111 1111 1111 1111 1010  (-6)

(Shortcut: ~x is always mathematically equal to −(x+1)-(x + 1)−(x+1)).

2. How Bit-Shift Operators Work

Let's use a = 5 (Binary: 0101) and shift it by 1 position.

E. Left Shift (<<) Shifts the bits to the left by the specified number of positions, filling the rightmost bits with 0. 

   0101  (5)
   5 << 1
 --------
   1010  (10)

Mathematically: 5×21=105 \times 2^1 = 105×21=10

F. Signed Right Shift (>>) Shifts the bits to the right, preserving the sign bit (leftmost bit) to maintain whether the number is positive or negative.

   0101  (5)
   5 >> 1
 --------
   0010  (2)

Mathematically: 5/21=25 / 2^1 = 25/21=2 (integer division)

G. Unsigned Right Shift (>>>) Shifts bits to the right, but always fills the leftmost bits with 0, completely ignoring the original sign of the number.

For positive numbers, it looks identical to >>:

   0101  (5)
   5 >>> 1
 --------
   0010  (2)

For negative numbers, the difference becomes massive because the sign bit (1) is pushed right and replaced by a 0, turning the negative number into a very large positive number (in a 32-bit space):

  -5 in 32-bit binary:
  1111 1111 1111 1111 1111 1111 1111 1011

  -5 >>> 1 shifts everything right and inserts a 0 on the left:
  0111 1111 1111 1111 1111 1111 1111 1101  (2,147,483,645)

9. Java is Strictly Pass-By-Value


A critical core concept: Java passes everything by value, never by reference.


    

  • Passing Primitives: A copy of the actual primitive value is passed. Modifying the parameter inside the method does not affect the caller's variable.
    • 

  • Passing Reference Variables: A copy of the reference address is passed. 
      

    • Mutating object state via the copied reference affects the original object.
      • 

    • Reassigning the reference itself (param = new Object()) does not reassign the caller's original reference variable.
      • 

    

    •

3. Hashing Internals & the equals() and hashCode() Contract


When you insert a key into a HashSet or HashMap:


    

  1. hashCode() is called to calculate the initial integer hash value.
    2. 

  2. The JVM calculates bucket index: index = (n - 1) & hash.
    3. 

  3. If collision occurs in that bucket, equals() is called on existing keys in that bucket:
      

    • If equals() returns true, the value is updated (no duplicate key).
      • 

    • If equals() returns false, a new node is linked.
      • 

    

    4. 

  4. Java 8+ Bucket Treeification: When bucket size exceeds 8 nodes and array capacity ≥64\ge 64≥64, the bucket linked list converts into a Red-Black Tree, improving worst-case search from O(n)O(n)O(n) to O(log⁡n)O(\log n)O(logn)!
    5. 



The Official Contract:


    

  • If a.equals(b) == true, then a.hashCode() == b.hashCode() MUST always be true.
    • 

  • If a.hashCode() == b.hashCode(), a.equals(b) may or may not be true (hash collision).
    •

A. Initial Capacity and Load Factor (Topic 92)


    

  • Initial Capacity (16): The number of buckets created in the hash table when instantiated with the default constructor (new HashSet<>()).
    • 

  • Load Factor (0.75f): A measure of how full the hash table is allowed to get before its capacity is automatically increased. Default is 0.75 (75% full).
    • 

  • Threshold Calculation:
Threshold=Capacity×Load Factor=16×0.75=12\text{Threshold} = \text{Capacity} \times \text{Load Factor} = 16 \times 0.75 = 12Threshold=Capacity×Load Factor=16×0.75=12
When the 13th element is inserted, the internal bucket array automatically triggers resizing!
    • 



B. Resizing and Rehashing Mechanics (Topic 93)


    

  • Resizing: The capacity of the bucket array doubles (2×2\times2×): 16→32→64→128…16 \rightarrow 32 \rightarrow 64 \rightarrow 128 \dots16→32→64→128…
    • 

  • Rehashing: Because bucket indices are calculated as index = (capacity - 1) & hash, doubling the capacity changes the bitmask (capacity - 1). Therefore, every existing entry must have its bucket index recalculated and moved to its new bucket.
    • 

  • Performance Note: Rehashing is an O(n)O(n)O(n) expensive operation. If the expected element count is known upfront, initialize the set with adequate capacity (new HashSet<>(expectedSize / 0.75f + 1)) to avoid costly rehashing cycles.

class BankAccount {
    private int balance = 0;

    // Consumer method: waits if balance is insufficient
    public synchronized void withdraw(int amount) {
        System.out.println("Withdrawal requested for: " + amount);
        while (this.balance < amount) {
            System.out.println("Balance is low (" + this.balance + "). Waiting for deposit...");
            try {
                wait(); // release lock and wait
            } catch (InterruptedException e) {
                System.out.println(e);
            }
        }
        this.balance -= amount;
        System.out.println("Withdrawal completed! Remaining Balance: " + this.balance);
    }

    // Producer method: deposits and notifies waiting thread
    public synchronized void deposit(int amount) {
        System.out.println("Depositing: " + amount);
        this.balance += amount;
        System.out.println("Deposit successful! Current Balance: " + this.balance);
        notify(); // wake up waiting thread
    }
}

3. Transaction Management (commit and rollback)


Disable auto-commit, execute multiple operations atomically, commit on success, and rollback on any error.

package com.cdac;

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.PreparedStatement;
import java.sql.SQLException;
import java.util.Scanner;

public class TransactionManagement {

    public void transferMarks() throws ClassNotFoundException {
        Scanner s = new Scanner(System.in);
        System.out.println("enter source student id, target student id, marks to transfer");
        int fromId = s.nextInt();
        int toId = s.nextInt();
        int marks = s.nextInt();

        Connection con = null;
        try {
            // loading driver
            Class.forName("com.mysql.cj.jdbc.Driver");

            // get connection
            con = DriverManager.getConnection("jdbc:mysql://localhost:3306/pgcpac", "root", "cdacacts");

            // 1. disable auto commit
            con.setAutoCommit(false);

            // 2. deduct mark from first student
            String q1 = "update student set mark = mark - ? where id = ?";
            PreparedStatement pmt1 = con.prepareStatement(q1);
            pmt1.setInt(1, marks);
            pmt1.setInt(2, fromId);
            pmt1.executeUpdate();

            // 3. add mark to second student
            String q2 = "update student set mark = mark + ? where id = ?";
            PreparedStatement pmt2 = con.prepareStatement(q2);
            pmt2.setInt(1, marks);
            pmt2.setInt(2, toId);
            pmt2.executeUpdate();

            // 4. commit if both queries succeed
            con.commit();
            System.out.println("transaction committed successfully");

        } catch (SQLException e) {
            // 5. rollback if any query fails
            try {
                if (con != null) {
                    con.rollback();
                    System.out.println("transaction rolled back due to error");
                }
            } catch (SQLException ex) {
                ex.printStackTrace();
            }
        } finally {
            try {
                if (con != null) {
                    con.close();
                }
            } catch (SQLException e) {
                e.printStackTrace();
            }
        }
    }
}

        Connection con = DriverManager.getConnection("jdbc:mysql://localhost:3306/pgcpac", "root", "cdacacts");

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.CallableStatement;
import java.sql.Types;
import java.sql.SQLException;

class StoredFunctionDemo {
    public static void callStudentMarksFunction(int studentId) {
        String url = "jdbc:mysql://localhost:3306/pgcpac";
        String user = "root";
        String pass = "cdacacts";
        String functionSql = "{? = call getStudentGrade(?)}";

        try (Connection con = DriverManager.getConnection(url, user, pass);
             CallableStatement cs = con.prepareCall(functionSql)) {

            cs.registerOutParameter(1, Types.VARCHAR);

            cs.setInt(2, studentId);
